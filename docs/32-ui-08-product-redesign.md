# UI-08：产品化界面改造

2026-10-15。状态：planned → ready → in_progress → in_review → done。交付与最终验收见[33](33-ui-08-delivery.md)。依赖：UI-07、P1-01b。

## 1. 背景与目标

用户反馈：界面读起来像开发演示，不像成熟产品。审计（文案、Web Interface Guidelines、产品成熟度）结论：

- 视觉是通用 SaaS 卡片套件：浅蓝底、通用蓝、系统字体、所有内容放进同款圆角卡片、每块都有入场动画。
- 文案有大量对仗口号；里程碑编号、评审与验收记录直接展示给用户；同一限制在一页内重复多次；同一概念有多种叫法。
- 缺少成熟产品的基础：共享工作区布局、全局环境状态、总览页、设置/环境页、URL 同步的选中状态、可复制 ID、骨架加载、统一反馈、按页标题、404 与错误页。

目标：在不夸大能力的前提下，让工作区像一个可每天使用的开发工具。

用户已确认的决策（2026-10-15）：

1. 视觉方向：中性工程风。
2. 信息架构：重组（总览、复现唯一入口、修复与回归合并、环境与接入、项目记忆移出导航）。
3. 开发进度类内容移出产品界面，改写 AGENTS.md 与 [13](13-ui-progress.md) 的前端能力同步门禁。
4. 新增依赖：`geist`（本地字体）与 CodeMirror 6（调用检查编辑器）。

## 2. 视觉系统

**令牌**（`frontend/app/styles/foundation.css`，浅色/深色两套，同名变量）：

| 角色 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bg` | #F6F7F8 | #0E0F11 | 页面底 |
| `--surface` | #FFFFFF | #16181B | 面板 |
| `--surface-2` | #F0F1F3 | #1C1F23 | 表头、次级填充 |
| `--border` | #E2E4E8 | #272A30 | 分隔与边框 |
| `--text` / `--text-2` / `--text-3` | #15171C / #4A505A / #767C86 | #E8EAED / #A9AFB8 / #7D838D | 三级文字 |
| `--accent` | #3E4BDB | #8B95FF | 唯一强调色：主操作、焦点、选中 |
| `--pass` `--fail` `--unknown` | #187A48 / #C0313A / #9A5A07 | #4CC38A / #F07070 / #E2A64C | 仅用于判定结果 |

- 字体：拉丁文与数字 Geist Sans，代码、ID、路径、命令 Geist Mono；中文使用系统字体（PingFang SC / Microsoft YaHei）。
- 字号阶梯（工作区）：12 / 13 / 14 / 16 / 20 / 24；落地页展示字号单独定义。
- 圆角：4（徽标、小控件）、6（按钮、输入）、8（面板）、12（仅落地页大块）。面板不加阴影；阴影只给浮层（弹出层、对话框、提示）。
- 层级靠分隔线和留白，不靠层层卡片。次要区块用分隔线，不再套卡片。
- 判定色只表达结果，不做装饰；强调色不与判定色混用。
- 标志性元素：**JSON Pointer 路径**（`PathTrail`）。用分段等宽样式展示问题位置，在调用检查、运行报告、落地页一致出现。

**动效**：只回应状态变化——运行中的状态点、新事件行的短暂高亮、浮层与抽屉 150ms 展开。移除通用入场动画。落地页只保留一次编排好的示例检查演示。全部遵守 `prefers-reduced-motion`。

## 3. 信息架构

| 导航 | 路由 | 内容 |
|---|---|---|
| 总览 | `/workspace` | 环境状态、最近运行／分析／修复、快速开始 |
| 调用检查 | `/workbench` | 导入或编辑调用证据并检查（CodeMirror） |
| 复现 | `/workspace/tasks` | 唯一的场景运行入口与运行记录 |
| 分析 | `/workspace/diagnosis` | 发起分析、分析记录与证据 |
| 修复 | `/workspace/repairs` | 修复任务；标签「代码差异」「回归结果」 |
| 环境与接入 | `/workspace/connections` | 本机服务、Docker、模型配置状态；角色与工具接口；CLI 命令 |

- URL 片段保持不变，减少文档与测试断链。`/workspace/regression` 重定向到 `/workspace/repairs?tab=regression`，`/workspace/memory` 重定向到 `/workspace`。
- 所有工作区页面共用 `app/(app)/layout.tsx` 外壳：侧栏、环境状态、主题切换。页面只渲染内容。
- 选中记录写入 URL（`?run=`、`?analysis=`、`?task=`、`?tab=`），可分享、可后退。
- 每个路由有独立 `<title>`；新增品牌化 404 与错误页。

## 4. 文案规范

**语气**：对开发者直说。用平实动词、主动语态。不写口号、对仗、排比、「不是…而是…」，也不写「一目了然」「有据可依」之类空话。

**规则**

1. 页面标题就是模块名；副标题一句话，说明在这里能做什么。
2. 按钮用动词说清结果；同一动作在按钮、进行中、完成提示中用同一个词（停止 → 正在停止… → 已停止）。
3. 每个模块只用一行状态说明能力边界（网页可用 / 网页只读 / CLI 可用 / 待开发），同一限制一页只说一次。
4. 不向用户展示里程碑编号、评审、验收、测试数量；这些留在 docs。
5. 错误提示说明发生了什么、用户该做什么；不道歉，不含糊。
6. 空状态给出下一步操作。
7. 合成数据始终标注「内置示例」，不包装成用户的真实运行。
8. 技术标识（ID、摘要、路径）用等宽字体，可复制，默认折叠在详情里。

**术语表**

| 概念 | 统一用词 |
|---|---|
| 导入的 JSON | 调用证据 |
| JSON Schema | 契约 |
| 检查发现的问题 | 不符合项 |
| 检查结论 | 通过 / 不通过 / 无法判定 |
| 场景执行功能 / 每次执行 | 复现 / 运行 |
| 故障类型 | 场景 |
| 项目自带数据 | 内置示例（合成数据） |
| 一次模型协作 | 分析 |
| 修复角色的输出 | 修复建议 |
| 应用到隔离副本的结果 | 候选 |
| 候选与原代码的差别 | 代码差异 |
| 原代码 | 基线 |
| 基线与候选逐项对比 | 回归结果 |
| 后端进程 | 本机服务 |
| 用量未结算 | 用量待确认 |
| /updates | 更新记录 |

## 5. 实施批次

1. 基础层：令牌与基础样式、字体、共享外壳、侧栏与环境状态、通用组件（PageHeader、StatusBadge、CopyId、RelativeTime、Skeleton、EmptyState、Toast、ConfirmDialog、Tabs、PathTrail）、格式化工具、路由元数据、404/错误页、重定向、总览页。
2. 页面：复现、分析、修复（差异查看器与回归标签）、调用检查（CodeMirror）、环境与接入、落地页与更新记录。
3. 门禁：E2E 文案与结构同步、浅深色 × 1440/390 截图与 axe、独立代码评审、修复后复审、文档与台账更新。

## 6. 验收

- `npm run typecheck`、`npm run build` 通过；E2E 全部通过；浅深色 × 桌面/手机 axe 零违规，无横向溢出。
- 工作区界面不出现里程碑编号；能力状态只用四种用户状态；不夸大网页能力（修复与回归仍为网页只读）。
- 环境状态实时反映本机服务、Docker 镜像、模型配置与执行槽，后台标签页暂停轮询。
- 选中记录与标签写入 URL，刷新后保持。
- 不改 Python 行为与 API 契约；不新增写请求类型。
- 独立评审无未修复的 Defect P0/P1。
