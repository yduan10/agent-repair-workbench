# P0-04：真实运行记录的只读网页

2026-10-13；P0-04 实现与独立评审完成，最终进度以台账为准。

## 设计计划与自审

采用 frontend-design 的两阶段过程，沿用 UI-02 / UI-03：云蓝 `#EEF3FA`、纸面 `#FFFFFF`、墨色 `#16243D`、钴蓝 `#335CDE`、深海 `#101B30`、夜间文字 `#E9F0FC`；系统中文无衬线正文与等宽摘要。桌面左侧最近运行、右侧选中证据，手机上下排列；不改现有侧栏、主题与减少动效偏好。

自审后不采用总数指标卡或默认自动选第一项。用户要核查具体一次执行，主体直接展示真实记录与事件；刷新不改变选择，不把项目开发测试数量填成用户任务。能力进度区仍明确是有日期的开发快照，运行区域单独展示 API 返回的状态。

## 数据与交互边界

- 页面仅发 GET `/api/runs?limit=50`、GET `/api/runs/{uuid}`、GET `/api/runs/{uuid}/report`。精确三个代理规则，不开放执行、取消、删除、任意命令或任意后端地址。
- `AWB_API_PORT` 为仅服务器端测试配置，限定 1024～65535 数字，目标始终固定 `127.0.0.1`，默认 8030。测试 8031 与产品 8030 独立；Next build 会固化 rewrite，产品部署前用默认值重新构建。
- 所有响应先按流累计限 1 MiB、15 秒超时、UTF-8 / JSON，再经 Zod strict schema 校验。列表最多 50、事件最多 100，UUID / 摘要 / 枚举 / 日期 / 版本有边界；重复运行 ID、错误详情关联和逆序事件拒绝。
- HTTP 异常不读取并显示原始错误正文；页面用固定提示，支持刷新和重试。刷新失败时明确标注旧列表可能过时。
- 选择、刷新与卸载会终止过期请求；晚到数据不能覆盖当前选择。没有自动选择第一项、后台轮询或执行重试。
- 报告校验完整版本结构、`record_id` 对应逻辑运行、`run_id` 对应执行尝试，并验证原始响应字节 SHA-256 等于详情摘要；下载保留原字节，不重新序列化。
- 明示当前记录来自已审核的合成故障场景，容器执行与持久状态是真实记录；场景名显示中文与英文，避免被理解为任意用户项目历史。
- 状态区分 queued / running / succeeded / failed / cancelled / outcome_unknown；结果未知不代表无副作用。事件只显示固定种类与时间，无 lease token。
- 首页、侧栏、任务页共用能力目录，验收通过后统一显示“记录可用”。迭代历史新增 P0-04，保留 8 条已完成记录。

## 自动验证

`npm run test:runs-live` 创建独立系统临时目录 `awb-p004-e2e-*`，设置 `AWB_STATE_DIR=<tmp>/state`、`AWB_API_PORT=8031`、`PW_PORT=3011`，先 build，再由 Playwright 起独立 API / 前端。测试禁止复用已有服务，结束后停止服务并清理临时库。不会读写产品默认数据库。Python seed helper 仅接受标志开启、系统临时根目录内约定名称且尚不存在的 state 路径。

真实 SQLite 测试通过生产 RunStore 写入合成契约测试记录，再走实际 API 和浏览器：空库读取不创建数据库、6 种状态、选择与事件、报告原始字节和摘要、断网恢复、缺报告禁用。它验证存储与 Web 集成，不把这些记录宣称为真实 Docker 执行；真实 Docker CLI → 产品 API → 页面由主 Agent 单独验收。

其他浏览器用例用 mock 只验证异常边界：服务错误、越界正文、私有字段、重复 ID、未知状态、坏日期、过多记录、错关联、逆序事件、404、切换/卸载取消、哈希不符。包含桌面/手机有数据详情的 axe 与溢出检查，沿用 36 个主题/页面/尺寸组合。
