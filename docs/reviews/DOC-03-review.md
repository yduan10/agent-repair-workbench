## 2. 生产事故风险推演

以下为初审设计反例，修订已关闭，不声称已在不存在的实现中复现。

**D01：检查发现问题却提前结束修复任务。** 用户请求分析/修复输出字段不一致，确定性检查器自然能识别违反 schema；旧 A01 要求此场景模型调用数为零，旧流程允许直接返回报告。如果照此实现，用户要求的原因分析与候选建议无法到达。影响单任务目标完成，错误地把“检出问题”当“完成修复”。

**D02：测试文件未改，验收却被候选控制。** 候选 Python 代码若与权威 pytest 运行器共解释器，可能修改内存中的断言/收集结果，或打印伪造 JUnit/JSON 成功报告；验收文件仍只读且哈希相同。旧规格只明确文件冻结和摘要检查，未限定可信判定进程，可能把不可信候选的自报成功标为 candidate_verified。影响单候选通过标签及后续用户接受。
