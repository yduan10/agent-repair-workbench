### 3.5 失败第1次：可以确定什么

任务 `b2976e0f-535a-480c-afa8-4ddc69e428df`，output_mismatch / single_role。

1. 顺序是读取契约T02 → 真实复现T05 → 读取源码T03 → 应用候选T06 → 再读证据T01 → 第6次模型返回不可用 → 终止。T05已独立确认原错误。
2. 已有1个committed候选；**没有T07比较记录**，因此该候选不能算通过或算“补丁行为已失败”。它属于未验证候选。
3. 最后一项模型请求持久状态failed / `MODEL_RESPONSE_INVALID`，已知输入8374、输出392tokens；任务最终inconclusive / `INVALID_MODEL_OUTPUT`。所有已知用量已结算，预留0，唯一容器已回收。
4. 现有持久证据只能确定是模型响应/决策协议未形成可执行下一步，不能进一步声称“JSON缺哪个字段”“网关返回空choices”“提示词必然导致失败”或“8192输出不够”。`repair_store/store.py`的 `_finish` 在reply含错误时统一保存 `MODEL_RESPONSE_INVALID`（当前约739行）；controller在约178行将不可用决策终结为 `INVALID_MODEL_OUTPUT`。细粒度子错误未持久化，模型原文也按策略未保存，因此具体原因不可追溯。
5. 后续建议：单独登记安全结构化错误分类改进（如传输/响应封装/决策结构/输出截断），只持久化枚举和验证阶段，不保存模型原文。以新版本独立回归评估；**不修改本次冻结Prompt/代码、不补跑第1次替换结果、不放宽输出schema**。

此项是当前可观测性的明确边界，未违反本期要求的保守停止、用量结算或不得伪造通过。不把真实模型非100%成功等同实现缺陷，也不以此隐藏后续可靠性改进。
