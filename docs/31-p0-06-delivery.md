# P0-06：隔离修复与冻结回归交付记录

2026-10-15。状态：planned → ready → in_progress → in_review → done。此文汇总交付证据，不把工程测试通过当作任意项目修复能力。

## 1. 复现要交付什么

复现建立修复前的基线：同一审核源码、依赖、输入和执行配置，宿主确认具体哪条规则失败。之后模型在授权函数范围提出候选，应用到隔离副本；由模型进程之外的宿主验收器运行同一套检查，对照基线和候选。

用户最终应得到：具体问题、实际代码差异、原错误是否消失、正常行为是否回归、证据版本、用量与未确定事项。单独的“失败”状态不是修复完成。

任务总览的四场景（正常、工具错误、超时、响应丢失）用于验证执行与故障处理。选择“工具错误”会主动注入错误，报告必须同时区分调用失败与“观察到预设故障”。这个入口不会自动把旧任务变成模型修复任务。

## 2. 当前交付范围

| 环节 | 实现 |
|---|---|
| 检查与复现 | 读取审核证据和授权源码；T05在受控容器确认基线错误 |
| 候选应用 | T06只替换冻结函数范围，独立快照，不改用户原项目 |
| 独立验证 | T07四个新容器，对照基线/候选×原错误/正常路径；宿主判定 |
| 运行控制 | 持久预算、请求去重、最多两候选、超时取消与精确回收 |
| 中断恢复 | 默认只读inspect；明确apply后清理匹配孤儿，未知不自动重跑 |
| 网页 | 候选差异、逐项回归、版本核验、历史结果和用量；技术标识折叠 |
| 人工接受 | 尚未开放；candidate_verified不代表已接受或写回项目 |

固定审核案例包括：返回类型错误 `output_mismatch`，以及静态类型合法但业务计数偏移 `counter_offset`。后者由独立评审者先定义，保持Prompt1.4及相同输入序列、业务断言；仍是同一合成服务的不同故障，不是跨项目泛化证据。

模型修复从CLI发起；网页可发起既有诊断分析及四场景复现，修复页面此阶段只读。完整网页修复/审批归P1-01。

## 4. 真实模型结果

冻结实验已完成，12次预先登记的尝试全部保留，没有删除失败或补跑替换：

| 案例 | 单角色 | 三角色 |
|---|---|---|
| 返回类型错误 output_mismatch | 2/3验证通过 | 3/3验证通过 |
| 计数值偏移 counter_offset | 3/3验证通过 | 3/3验证通过 |

共11次通过、1次不可判定。失败发生在第6次模型返回之后：已生成一个隔离候选，但尚未发起T07回归，不能宣称候选正确或错误。持久记录只支持“模型响应未形成有效决策”，不足以确定具体解析子因，也没有截断或预算超限证据。

单角色共215,801 tokens，平均22.19秒；三角色共228,413 tokens，平均24.70秒。该样本不能证明多角色优越，也不能作为任意项目修复率。另一次三角色任务先拒绝第一个候选，再验证第二个候选，两个结果均保留。

独立审计确认：158个冻结文件无变化；12任务、13候选、12次T05、12次T07、60个容器执行全部核对；资源全部回收；所有用量完整结算。见[完整审计](reviews/P0-06-heldout-model-review.md)。材料在 `artifacts/p006-model/heldout-v1`，本机实验状态库独立于用户主库。

工程回归：默认后端1396 passed / 66 skipped；两案例真实Docker10 passed；Ruff检查/格式、mypy123个生产文件、uv锁验证通过。默认跳过项不算验收通过；真实Docker与浏览器门禁单独记录。最终网页完整回归181 passed / 9 skipped、真实控制台3 passed / 1 skipped与真实修复读取2 passed；各组存在重叠，不相加。网页整合与失败重验见[UI-08交付](33-ui-08-delivery.md)。

早期调试记录保留：路径前置拒绝、不可共享目录、重复取证、错误角色调用、候选身份复制错误、提前结束以及未知结果。Prompt1.4开发轮单/三各3次通过，但只有一个开发案例；接入第二案例修改可信实现后，必须同版本重跑两个案例，不能跨版本拼成成功率。[阶段实验](26-p0-06-candidate-verification.md)和[六次材料审计](reviews/P0-06-model-cohort-review.md)记录完整边界。

## 5. 版本、数据与部署

- 复用已显式升级的本地SQLite schema0007，本批案例扩展不重写旧记录或做自动迁移。
- 案例由持久baseline的manifest/file/tree固定绑定推导；新list/detail API为schema2，diff/comparison仍为schema1。前后端须同步部署。
- 业务用例和SUITE摘要不变；可信实现改动产生新ORACLE摘要。旧成功保留历史结论，当前核验按旧版本不匹配处理，不静默重签。
- 用户主库不灌入实验记录；模型实验、Docker故障和浏览器实链路均用独立状态目录。
- 密钥不入库，原始模型回复不持久化；费用没有单价配置即显示未知。没有进行commit、push或远端发布。
