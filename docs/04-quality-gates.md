# 测试、评估与独立评审

## 1. Definition of Ready / Done

Ready：有任务 ID、输入输出、边界、依赖、负向场景和可执行验收。Done：实现完成、固定验收通过、静态检查通过、独立评审完成、阻断缺陷已修复并复审、文档和证据已同步。缺任一项保持 in_progress / in_review。

## 2. 测试层次

| 层 | 验证内容 | 是否调真实模型 |
|---|---|---|
| 单元/性质 | schema 语义、状态不变量、路径编码、输入边界 | 否 |
| 集成 | 实际 MCP SDK/stdio、进程树、SQLite 恢复 | 否 |
| 端到端 | 固定案例→复现→候选→验收 | 模拟用于 CI，真实用于版本验收 |
| UI/API | 真实HTTP检查、预览交互、桌面/手机布局、axe、文件保真、取消并发 | 否 |
| 对抗 | 注入、越权、篡改测试、超限、原始值泄漏 | 按层分开 |
| 独立评估 | 隐藏用例、公开故障、未参与开发的工具项目 | 固定模型和预算 |

每个故障测试必须在缺陷重新引入时失败；避免只断言 mock 或内部调用次数。自然语言生成不作为唯一 oracle。CI 不要求对所有历史工具无限扩覆盖；按当前改动风险选择测试。

P0-05 / P0-06 的具体必测用例、数据集字段和自研/第三方测试责任见 [17 实施规格](17-agent-tools-testing-plan.md)：A01～A15、R01～R11。设计矩阵是后续实现门禁，不计入已通过测试数量。角色单测必须纳入pytest发现；fake模型确定性CI与真实DeepSeek接入验收分开记录。

## 3. 评估口径

| 指标 | 定义 |
|---|---|
| 诊断精度 | 经独立确认的诊断数 / 所有给出确定诊断的样本数 |
| 诊断覆盖率 | 给出确定诊断的样本数 / 全部适用样本数 |
| 正确修复率 | 修复原失败且固定回归通过的任务数 / 全部可修复评估任务数 |
| 回归率 | 引入至少一个新固定用例失败的候选数 / 所有实际执行候选数 |
| 执行成本 | 模型 input/output tokens、请求数、墙钟时间、CPU/容器时长分别报告 |
| 接入成本 | 每项目配置/代码修改量、人工步骤和实测时间 |

分母为 0 标 N/A，不写 0% 或 100%。按真实历史问题、合成注入分别统计。样本量、随机种子、模型配置、版本和预算随结果保存；重复运行报告全部分布，至少均值/中位数/失败数。小样本不得宣称商业可靠性。

P0-01 无模型诊断和修复指标；它只记录检查结果，不能把契约负例检出率当根因诊断准确率。

## 4. 独立评审流程

1. 文档评审：专职 reviewer 读约束、架构、台账、规格，核对可执行性、一致性、范围和门禁。
2. 代码评审：另一独立上下文读实现、调用方、测试及规格；可以运行测试、构造反例，默认不编辑实现。
3. 实现者修复，给出发现 ID→修改→验证映射；评审者重新检查改动及相关风险。
4. 报告记录实际文件和 SHA-256 清单（无 Git 时）或 commit SHA+diff；变动后必须审增量。
5. 评审 skill：`auditing-enterprise-code-quality`。覆盖十二维度；阶段不涉及的维度说明不适用。评分反映指定范围，不是整产品生产认证。

如 GitHub Code Review 插件仅提供远端 PR/CI 检查，不能以“工具可用”冒充已执行本地代码评审。本项目使用用户授权的专职 reviewer 子 Agent，报告保存 `docs/reviews/`。不自动创建远端 PR。

## 5. 缺陷等级与门禁

| 级别 | 本项目判定 | 要求 |
|---|---|---|
| Defect P0 | 可达的凭据泄漏、越权写、数据损坏、无界执行等关键失守 | 立即阻断；修复并复审 |
| Defect P1 | 错误报告通过、失去状态一致性、破坏固定验收、现实资源泄漏 | 任务 done 前修复 |
| Defect P2 | 非立即失效的可测试性/观测/设计不足 | 记录跟踪 ID、负责人、迭代；按评审门禁处理 |
| Defect P3 | 局部命名/文档润色 | 不掩盖高优先级问题 |

默认审查严苛度 Mission-Critical；对本地阶段明确适用范围。未经验证的猜测标 suspected，先构造反例核实，不能将主观偏好当缺陷。评分规则存在冲突时以有证据的风险和本项目“未修复 P0/P1 不 done”执行，报告解释依据。

## 6. 发布、恢复与依赖

依赖由 uv 解析生成锁文件，不手工修改锁。记录新增直接依赖、必要性、许可证、锁定版本和安全检查；漏洞扫描结果仅覆盖已知公告，不证明没有漏洞。CI 安装用 frozen 模式；Python 3.12 是当前保证的版本。

M0 首版是本地 CLI；UI-01 增加回环地址网页/API，仍无公网服务。P0-04 增加本地 SQLite 与 Alembic 迁移；含数据降级拒绝，活动 WAL 用 SQLite backup API 备份，再恢复到独立目录验证运行、事件和报告一致。前端由 npm ci 安装 lock 对应版本，经 TypeScript/production build/真实浏览器测试和独立界面评审；预览页面有明确来源标记。恢复方式是停用当前版本、恢复前一份已验证源码/锁文件；报告格式有版本。首次版本无已发布前一版，应明确这一限制。后续 schema 迁移须有备份及恢复演练。

CI 配置在本地通过相同命令不等于 GitHub Actions 已在远端通过。首次公开发布前补仓库许可证决定、远端 CI、依赖漏洞扫描及安装验证，发布状态另记，不能由一次本地评审推导“已上线”。
