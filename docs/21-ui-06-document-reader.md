# UI-06：站内工程文档阅读器

日期：2026-10-13。状态：done。

## 用户纠正与范围

工程文档必须在本站新页面阅读，视觉风格与产品一致，不把 GitHub 当正文阅读页。UI-05 的外部文档目录被本批替换；GitHub 仅保留源码入口和外部资料引用。

- `/docs` 是上手与导航页；`/docs/02-architecture` 等独立路由展示项目 Markdown 原文。
- 文档源与代码同仓维护，构建时读取 README 与 docs 下的 Markdown，文档更新随构建发布；没有第二份手工复制的正文。
- 桌面左侧文档导航 / 中间正文 / 右侧章节目录，窄屏改可展开目录；沿用产品浅色、深色及系统主题。
- 统一标题、列表、引用、表格、代码块和继续阅读排版；表格与代码可键盘聚焦、横向滚动。禁止整页横向溢出。
- Markdown 内相对文档链接映射为本站路由；非文档源码和外部官方参考链接才打开外站。

## 实现与边界

使用固定版本 `react-markdown` 10.1.0 与 `remark-gfm` 4.0.1，服务端渲染，不执行 MDX、不启用原始 HTML、不加载文档远程图片。路由只能命中构建时已登记的文档集合，不能把请求参数直接拼成文件路径。拒绝危险 URL 协议与根外相对路径。

设计继续使用 frontend-design skill：既有云蓝/深色语义变量、中文系统字体和等宽代码字体。通过内容宽度、章节层级和导航表达阅读结构，减少正文区域装饰。

## 验收

1. 工程文档入口均指向本站，浏览器前进/后退正常。
2. 正文来自真实文档，TOC 锚点及文档交叉引用可定位；未登记路径404。
3. 桌面/手机、浅/深色、axe、长表格/代码键盘可达；原产品页导航与检查回归。
4. 构建/类型检查、依赖公告扫描、独立 UI 代码评审后同步台账与开发记录。
5. 本批随源码推送，但不把站内阅读器算作模型 Agent 功能。
